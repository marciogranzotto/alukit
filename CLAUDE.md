# CLAUDE.md: AluKit

Guidance for agents (and people) working in this repository. The README is the user-facing
introduction; this file is how to change the code without breaking what it promises.

## What this is

AluKit plans builds made from catalog parts, starting with aluminium T-slot extrusion. A project
is **one JSON document** (`alukit.json`, plus `alukit.lock.json`, which pins the catalog data it
was derived from). From it AluKit derives the cut list, a priced BOM, per-bar machining, an order
list per supplier, checks, and a GLB. The same document is edited in three ways: in the browser
app (a local Node server and a three.js view), through the CLI, or by hand. **All three must stay
equivalent** (CLI parity, design §7).

The repository is **public**. Users' projects never live in it.

## Commands

Node comes from `.nvmrc` (26) via nvm; pnpm is pinned in `package.json` (`packageManager`).

```sh
source ~/.nvm/nvm.sh && nvm use        # every shell; tests use Node-only APIs
pnpm install --frozen-lockfile
pnpm lint                               # Biome (warnings allowed, errors not)
pnpm typecheck                          # tsc --noEmit
pnpm test                               # Vitest: unit, golden cases, CLI in-process
pnpm build                              # the app into dist/; serve, snapshot and e2e need it
pnpm test:e2e                           # Playwright, headless Chromium (SwiftShader)
node src/cli/main.ts catalog check forseti   # also: std, ref-hiwin
pnpm skill                              # regenerate skills/alukit from the command schemas
```

The CLI runs from the sources with no build step: `alias alukit="node $PWD/src/cli/main.ts"`.
`alukit serve <project>` starts the server and opens the app.

**Before any merge, run the whole sequence above, in that order**, and treat any failure as
blocking. CI runs the same steps, except the catalog checks, on every push.

Run one test file with `npx vitest run <path>` or `npx playwright test <spec> --workers=1`.

## How work is done here

- **Design first.** Behaviour lives in `docs/design.md`. When you change it, mark the changed
  text *2.3*, add bullets under a dated changelog heading at the top, and record the calls you
  made without asking in §14 (numbered; check the last number before adding one). Put the detail
  and reasons in a note under `docs/notes/`, and add it to the index.
- **Fix at the root, with the failing test first.** Write a test that fails for the reason the
  bug or gap exists, then fix the cause. Don't patch symptoms, and don't add special cases for one
  fixture.
- **Golden cases** (`G1`…, design §4.6) are worked examples. Each has an independent
  `by_hand.py` that computes the expected values without AluKit's code. A golden value moves only
  when the change is its cause, and the note says so. After a change, compare every golden's and
  every fixture's diagnostics before and after, and list what moved and why.
- **Every command keeps CLI parity:** a canonical form, undo, a CLI path, a CLI test, and
  regenerated skill docs (`pnpm skill`).
- **Catalog data comes from importers.** Never hand-edit generated catalog files; change the
  importer or its reviewed tables and rerun it. Values carry their source: printed, read, measured
  or estimated, with an uncertainty where it applies. Raw downloads live in the gitignored
  `.cache/`.
- **The test catalogs are fixed.** Golden values are computed from `tests/fixtures/catalogs/`, so
  changing them moves goldens.

## Tests that guard promises: never loosen them

- `tests/e2e/draw.spec.ts`: drawing a frame in the app gives a cut list **byte-identical** to the
  one the CLI builds.
- `tests/e2e/live.spec.ts`: a CLI edit appears in two open tabs **within 1 s**, at the same
  revision (design §12).
- `tests/e2e/view.spec.ts` counts **WebGL shader-program links across a revision and expects
  zero**. Don't create or dispose materials per revision; reuse them (a revision disposes the old
  model only after the frame that draws the new one). A lasting material that is first shown
  later (a gizmo part, the x-ray, a marker) needs a hidden object in the scene at startup, so the
  viewer's `renderer.compile` links its program before the first frame. A link count must be read
  after the frame that drew what it waits for (`RenderStats.modelFrame`, `badgeFrame`; the
  `waitDrawn` helper waits for the model's), never after "some frames".

When a timing test fails, **measure before blaming the machine**: run it alone, then A/B it
against the previous `main` under the same load. A recurring "load flake" was once a real cost
(shader relinks on every revision). Re-run, measure, and report; never raise a timeout to make it
pass.

## Conventions

- TypeScript with erasable syntax only (Node runs the sources directly). Preact with signals;
  three.js used directly; Zod 4 for schemas; Biome for lint and format.
- Imports from the core use the `#core/...` alias.
- Units are millimetres and degrees. Expressions (`src/core/expr.ts`) accept params and units
  wherever a length is typed.
- The UI's shared interfaces (selection and focus, targets, corners, tokens, the sheet registry,
  the command bar) are listed with their owners in `docs/ux/contracts.md`. Extend them there, and
  note the change.
- Tests that sweep many fixtures use one test per fixture (`it.each`); CLI probes run in-process
  through `capture`, not by spawning processes.
- Keep CSS within the token system (`src/ui/styles/tokens.css`): status is shape, word and colour,
  and text meets WCAG 2.2 AA in both themes.

## Commits and branches

- Commit messages say what changed and why, in plain sentences; merges name what they bring in.
- **No AI co-author trailers or attribution lines in commits.**
- The default branch is `main`. Work on a branch or worktree and merge with `--no-ff`. Don't
  delete remote branches.

## Public repository hygiene

- Never commit absolute local paths, credentials, or personal or company names, nor any user's
  project files.
- `internal/` and `.alukit/` are gitignored. Don't commit from them or link to them from public
  files.
